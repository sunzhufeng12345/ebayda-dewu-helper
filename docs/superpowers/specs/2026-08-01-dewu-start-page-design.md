# 得物申请新品起始页自动化设计

## 目标

把“申请新品”第一页加入现有新品草稿流程。程序每次从空白起始页开始，完成品牌、类目、适用人群和一张商品图片的填写，点击“创建新品发布申请”后进入现有详情页流程。起始页不填写商品链接；详情页仍沿用现有逻辑，默认只填写、不保存草稿，也不提交审核。

## 页面流程

1. 连接已登录的 Chrome 调试会话，定位 `stark.dewu.com/vueProduct/newProductApply/start` 起始页。
2. 校验起始页为空：品牌、类目、适用人群、商品链接必须为空，商品图片数量必须为零。发现残留值时停止，不删除或覆盖页面内容。
3. 打开品牌下拉框，选择第一个可见选项，并确认输入框回显非空值。
4. 打开级联类目，按顺序选择 `服装`、`上衣`、`卫衣`，确认输入框回显完整路径。
5. 打开适用人群下拉框，选择 `通用`，确认输入框回显。
6. 使用已解析媒体中的 `first_square[0]` 上传一张图片，等待页面出现一张上传成功的预览。
7. 再次确认商品链接为空，点击“创建新品发布申请”。
8. 等待当前标签页或新打开标签页进入 `/vueProduct/newProductApply/spuEdit/operation/`，激活该详情页并交给现有 `DewuAutomation`。

## 代码边界

- 新增起始页专用常量、页面对象和 Chrome 标签页选择逻辑；详情页字段定位和填写逻辑保持独立。
- 起始页定位基于表单标签、Element UI 组件类名、可见下拉选项和按钮文本，不使用坐标、元素序号或固定滚动距离。
- 当没有起始页时，可以在已连接的认证浏览器中打开固定起始 URL；已有起始页但不是空白页时不自动清理，避免误删人工数据。
- 创建操作只负责进入详情页，不点击保存草稿或提交审核。`--no-save` 的语义保持不变。
- 起始页流程使用 `MediaFiles.first_square`，不从轮播图或详情图中猜测替代文件；缺少该图片时在浏览器操作前报错。

## 错误处理

- 起始页数量不明确、域名不匹配、登录失效或页面结构无法确认时暂停并输出原因。
- 任一字段已有残留值、图片已有残留上传、目标下拉选项不可见或回显不一致时暂停，不继续创建申请。
- 创建后超时未进入详情页时返回 `paused_for_user`，保留当前 URL 和已完成阶段。
- 验证码、风控、权限弹窗和登录问题交由人工处理；自动化不绕过这些保护。

## 测试与验证

- 为起始页 URL 判定、空白页校验、首个品牌选择、三级类目选择、适用人群选择和首张方图来源添加单元测试。
- 先运行现有单元测试，再运行新增测试确认失败原因正确；实现后重新运行完整测试集。
- 测试通过后，在全新的起始页执行 `--execute --no-save`，先验证创建申请并进入详情页，再按实际出现的第一个错误逐步处理。
- 每个重要阶段完成后检查 Git 状态并创建中文提交，不提交虚拟环境、解压目录、浏览器 profile、压缩包或日志。
